# 콘텐츠 수급·카테고리 운영 기획

작성 2026-11-20. "실제로 사이트를 운영한다면 이벤트·할인 정보를 어디서 어떻게 가져오고 자동화할지, 카테고리는 적절한지"에 대한 검토와 기획.
숫자는 모두 2026-11-20 `eventor_dev`(운영 복제본) 기준.

## 1. 현재 진단

### 1-1. 콘텐츠가 멈춰 있다

| 구분 | 건수 | 만든 방식 | 마지막 등록 | 평균 조회수 |
|---|---|---|---|---|
| 이벤트 | 약 1,500 | 운영자 계정 5개가 손으로 등록([EM] Blue 504, EVENTOR. 365, 이벤터 175, Mindol 139, kayas 78…) | 2025-06 | 1~18 |
| 핫딜 | 68,732 | 크롤러가 **FM코리아 핫딜 게시판**을 Selenium으로 복사(30분마다) | 2026-08-17(크롤링 중단) | **0** |
| 축제 | 70(실시간) | 한국관광공사 API | 실시간 | - |

- 진행 중 이벤트 330건 중 **종료일이 실제로 남은 것은 17건**, 나머지는 "상시·별도 공지 시·소진 시"라 실제로 끝났는지 알 수 없다.
- 방문자는 하루 약 600명(2026-10 월 1.2만 명)인데 글 조회는 하루 0~7회. 들어와서 볼 게 없거나, 방문의 상당수가 봇일 가능성이 크다.

### 1-2. 핫딜 크롤링은 그대로 다시 켜면 안 된다

- 다른 커뮤니티가 모은 게시물(제목·본문·이미지)을 통째로 복사해 우리 글로 게시하는 방식이다.
  - 저작권(본문·이미지), 부정경쟁방지법의 데이터 부정사용(타인이 상당한 투자로 만든 성과물 무단 사용) 쟁점, 사이트 이용약관 위반 소지가 있다. 크롤링 경쟁사 DB 무단 수집으로 형사 처벌까지 간 국내 판례도 있다.
  - 상대 사이트 구조가 바뀌면 바로 깨지고(셀렉터 의존), 차단되기 쉽다.
- 검색엔진 관점에서도 손해: 6.8만 개의 복사 페이지(평균 조회 0)는 "얇은·중복 콘텐츠"라 사이트 전체 품질 평가를 끌어내린다.
- 결론: **FM코리아 크롤러는 폐기**하고, 이미 쌓인 핫딜은 정리(5절)한다. (2026-11-20 도커 이미지에서 Chrome 을 뺀 것과도 맞다)

### 1-3. 카테고리가 데이터에 비해 너무 많고 깊다

- 총 34개(공지·이벤트·자유·핫딜 4 + 이벤트 아래 그룹 7 + 세부 25). 이벤트는 3단계(이벤트 > 음식 > 피자).
- 세부 25개 중 **11개가 글 30건 미만**: 액세서리 0, 시즌기획전 3, 신발 4, 의류 5, 가전제품 9, 밥 12, 건강/미용 가전 13, 가구 14, 향수 21, 생활용품 21, 영화 29.
- 같은 분야 글이 그룹과 세부에 섞여 있다(예: 뷰티 그룹에 직접 237건, 그 아래 스킨케어 119건). 분류 기준이 사람마다 달랐다는 뜻.
- 핫딜 6.8만 건은 반대로 분류가 하나뿐이라 찾아보기가 어렵다.
- 모바일에서 3단계 메뉴는 누르는 횟수만 늘리고, 비어 있는 세부 카테고리는 "볼 게 없는 사이트"라는 인상을 준다.

## 2. 운영 방향(한 줄)

> **"남이 모은 걸 복사"에서 "공식 출처 + 회원 제보 + 제휴 피드를 자동으로 모으고, 사람은 검수만"으로.**
> 분류는 깊은 트리 대신 **분야 8개 + 태그(혜택 유형·브랜드·상태)**.

### 3-1. 출처별 평가

| **공공 API** | 축제(관광공사, 사용 중), 공연·전시(KOPIS 공연예술통합전산망), 영화(영화진흥위원회 KOBIS), 서울·지자체 문화행사, **예·적금 금리(금융감독원 "금융상품 한눈에")** | 공식 이용 허락 | 완전 자동 | 무료(키 신청) | ★★★ 1단계 |

## 4. 자동화 구조

```
 [수집기들]                  [정리]                          [게시]            [유지]
 공공 API ─┐
 제휴 피드 ─┼─▶ raw_items ─▶ 정규화 ─▶ 중복 제거 ─▶ 분류 ─▶ 검수 대기열 ─▶ 게시 ─▶ 만료·링크 점검
 공식 페이지┤   (원본 그대로)  브랜드·기간·  같은 링크·    분야·태그   자동 승인 / 운영자    (매일)
 회원 제보 ─┘                 가격·링크     비슷한 제목    신뢰도      승인·수정
```

| 단계 | 내용 | 구현 메모 |
|---|---|---|
| 수집기 | 출처마다 어댑터 1개(`SourceAdapter` 인터페이스: `fetch() → List<RawItem>`). 스케줄은 ShedLock(이미 사용 중)으로 한 인스턴스만 | 실패해도 다른 출처에 영향 없게 출처별 격리, 마지막 성공 시각 기록 |
| 원본 보관 | `raw_items(source, external_id, url, payload_json, fetched_at)` | 다시 정리할 때 재수집 없이 재처리 |
| 정규화 | 브랜드(사전으로 표기 통일: "스벅"→스타벅스), 기간, 가격, 혜택 유형, 대표 링크(추적 파라미터 제거) | 브랜드 사전 테이블 `brands`(이름·별칭·로고) |
| 중복 제거 | 정규화한 URL이 같으면 같은 글, 같은 브랜드 + 제목 유사도 높으면 병합 후보 | 회원 제보와 자동 수집이 겹칠 때 제보자를 "최초 제보"로 표시 |
| 분류 | 1차 규칙(브랜드 → 분야, 키워드 → 혜택 유형), 애매하면 LLM으로 분야·태그·3줄 요약 생성 | 요약은 원문 복사가 아니라 새로 쓴 문장 + 원문 링크. 신뢰도 낮으면 검수로 |
| 검수 | 공공 API·제휴 피드는 자동 게시, 공식 페이지·회원 제보는 운영자 승인(관리자 화면에 "검수 대기" 탭) | 하루 검수 목표 시간 30분 이내가 되도록 자동 승인 비율을 올려 간다 |
| 만료 | 종료일 지나면 자동 "마감"(지금도 상태 계산은 있음), "상시·소진 시" 글은 **30일마다 링크 점검**(404·리다이렉트·"종료" 문구 → 마감 후보) | 메인·목록·사이트맵에서 마감 글 제외 |
| 가격 점검 | 핫딜은 하루 몇 번 쇼핑 검색 API로 가격 확인, 오르면 "종료된 특가" 표시 | 호출 한도 안에서 최근 3일 핫딜만 |

### 4-1. 회원 제보 보상(이미 있는 포인트·등급 활용)

- 제보 등록 +10P, 운영자 승인 +50P, 추천 10개 이상 +100P, 허위·중복 제보는 0P.
- 등급이 높은 회원의 제보는 검수 없이 바로 게시(신뢰 회원 자동 승인).
- 주간 "베스트 제보자" 메인 노출.

## 5. 카테고리 개편안

### 5-1. 원칙

1. 분야는 **1단계 8개**만. 세부 분류는 트리가 아니라 **태그**로.
2. "무엇을 받나(혜택 유형)", "누구 이벤트인가(브랜드)", "언제까지인가(상태)"는 분야와 다른 축이므로 **필터**로 뺀다.
3. 글이 30건 미만인 분류는 만들지 않는다(빈 메뉴 금지).

### 5-2. 새 구조

| 축 | 값 | 화면 |
|---|---|---|
| 게시판 | 이벤트 · 핫딜 · 커뮤니티 · 공지 | 상단 메뉴 |
| 분야(8) | 🍕 음식·카페 / 👗 패션·뷰티 / 📱 디지털·가전 / 🏠 생활·리빙 / 🎤 문화·여가(공연·영화·팝업·축제) / 💳 금융·카드 / ✈️ 여행 / 🎁 기타 | 메인 아이콘 타일, 목록 상단 칩 |
| 혜택 유형(태그) | 할인·쿠폰 · 1+1·증정 · 응모·추첨 · 체험단 · 출석·적립 · 신규가입 · 무료 | 목록 필터 칩(여러 개 선택) |
| 브랜드 | 브랜드 사전의 브랜드 | **브랜드 페이지** `/brands/{이름}`(진행 중 이벤트 모음) — 검색 유입에 강함 |
| 상태 | 진행 중 · 마감 임박(7일) · 예정 · 상시 · 마감 | 목록 탭(기본 "진행 중") |
| 핫딜 | 쇼핑몰(쿠팡·11번가·G마켓…) × 분야 | 핫딜 목록 필터 |

### 5-3. 지금 카테고리 → 새 분야 매핑

| 지금(그룹 > 세부) | 새 분야 | 태그로 남길 것 |
|---|---|---|
| 음식 > 밥·치킨·피자·패스트푸드·카페&디저트 | 음식·카페 | 피자·치킨 등은 검색어로 충분 |
| 패션 > 의류·신발·액세서리·시즌기획전, 뷰티 > 스킨케어·메이크업·향수 | 패션·뷰티 | - |
| 전자제품 > 가전제품·모바일&PC·건강/미용 가전 | 디지털·가전 | - |
| 라이프 스타일 > 가구·생활용품 | 생활·리빙 | - |
| 엔터 > 콘서트/공연·굿즈&팝업스토어·영화, (축제) | 문화·여가 | 팝업 |
| 엔터 > 스포츠 | 문화·여가 | 스포츠 |
| 금융 > 카드혜택·예·적금 | 금융·카드 | - |

- 34개 → **게시판 4 + 분야 8 = 12개**.
- 옛 주소(`/posts?categoryName=피자`)는 새 분야 + 검색어로 301 이동해 검색엔진 색인을 지킨다.
- DB: `categories`는 그대로 두고 새 분야 행을 추가한 뒤 Flyway로 글을 옮기고, 옛 세부 카테고리는 숨김 처리(삭제하지 않음). `post_tags`, `brands` 테이블 추가.

### 5-4. 기존 핫딜 6.8만 건 정리

| 안 | 내용 | 장단점 |
|---|---|---|
| A(권장) | 원문 복사 본문·이미지를 지우고 제목·가격·쇼핑몰 링크만 남겨 "지난 핫딜 아카이브"로. 사이트맵에서 빼고 `noindex` | 법적 위험·얇은 콘텐츠 문제 해소, 내부 검색·가격 이력엔 활용 |
| B | 전부 비공개 처리(DB 보관) | 가장 안전, 대신 쌓인 데이터를 못 씀 |
| C | 그대로 둠 | 위험 유지 — 비권장 |

### 9-4. 무료 등급 안에서 운영하는 규칙

- **화면 요청 중에는 부르지 않는다**(G3 링크 채움만 예외, 실패하면 빈 양식으로 그대로 진행). 나머지는 모두 스케줄러가 대기열(`llm_jobs`)에서 꺼내 천천히 처리한다.
- 분당·하루 호출 수를 설정값으로 두고(한도는 AI Studio rate-limit 화면 값의 70%), 429가 오면 다음 주기로 미룬다. 하루 사용량·실패 수는 관리자 > 외부 연동에 표시한다.
- 보내는 것은 **공개된 페이지 글과 회원이 공개 게시용으로 쓴 글뿐**이다(무료 등급은 입력이 Google 제품 개선에 쓰임). 회원 이름·이메일 등은 보내지 않는다.
- Gemini 결과는 그대로 믿지 않는다. 날짜·가격이 원문에 실제로 있는지 서버가 확인하고, 맞지 않거나 신뢰도가 낮으면 검수 대기열로 보낸다.
- 공식 페이지는 사실 정보(제목·기간·혜택 유형)와 **원문 링크**만 쓰고, 본문은 Gemini가 새로 쓴 요약, 이미지는 복사하지 않는다(대표 이미지는 운영자·제보자가 올린 것만).
- 한도가 모자라면: 분류는 Flash-Lite로, 추출만 Flash로 나누고, 그래도 모자라면 유료 등급(소액)을 검토한다.

### 10-6. 사용자에게 보이는 것

- **게시물 상세 "AI 한눈에 보기"**: 3줄 요약, 혜택 크기·대상·참여 방법·난이도, 진행 중/종료 확인, 분야·혜택 태그(누르면 같은 조건 목록), 브랜드 이벤트 모아 보기.
- **비슷한 이벤트**: 같은 분야 진행 중 이벤트 중 혜택 유형·브랜드가 겹치는 순(SQL, Gemini 호출 없음).
- **이벤트 목록 필터**: 분야 8개·혜택 유형 7개.
- **혜택 트렌드 `/insights`**: 진행 중 수, 쉬운 이벤트 수, 종료 확인 수, 주간 리포트(Gemini 해설 + 추천), 분야·혜택 막대(누르면 목록), "클릭 몇 번이면 받는 혜택", 브랜드 순위, 2주 안 마감, 표로 보기.
- **브랜드 페이지 `/brands/{이름}`**: 진행 중 이벤트, 지난 이벤트, 평균 기간, 주로 하는 혜택 유형.
- **글쓰기 "링크로 채우기"**: 공식 페이지 주소로 제목·기간·종료 유형·3줄 요약(빈 칸만 채움).
- **메인**: 트렌드 미리보기 카드, 브랜드 스토리 → 브랜드 페이지.
- 모든 화면은 저장된 분석 결과만 읽는다. 화면을 열 때 Gemini 를 부르는 곳은 "링크로 채우기" 하나뿐.
